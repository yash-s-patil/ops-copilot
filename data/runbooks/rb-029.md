## Symptoms

- Many orders with the same carrier, hub or warehouse stop moving at the same time.
- Tickets arrive in a cluster, with the same carrier and often the same hub code on the last scan.
- The order timelines show `carrier_exception` events with the reason `weather_delay` or `vehicle_breakdown`, or no scans at all since a certain hour.
- The carrier notices page may show a strike, a flood, a road closure or a system failure. Sometimes support notices before the carrier announces anything.

## Checks

1. Count the affected orders you can see: same carrier, same hub or warehouse, same day. Ten or more is the threshold for an incident.
2. Check the carrier notices page and note the expected end time, if one is given.
3. Check whether a supervisor has already declared an incident. If so, a shared note names the incident, the cause and the message to use.
4. For each ticket, still open the order timeline. An order caught in an outage can also have its own problem, such as a failed address validation.

## Resolution

1. If no incident is declared and you count ten or more affected orders, tell a supervisor at once, with the carrier, the hub and three example order numbers.
2. The supervisor declares the incident, confirms the cause with the carrier's account manager and writes the shared customer message.
3. Reply to each affected customer with the shared message, adding their order number and nothing speculative. Do not give a delivery date until the carrier provides one.
4. Add the incident name to each ticket note so the tickets can be found and updated together.
5. Do not raise an individual trace for each order during an incident. The carrier's account manager handles them as a batch.
6. When the carrier recovers, check each ticket's order for a new scan before resolving it.

## Compensation

- An outage does not change the refund rules. Each order is judged on its own delay and its customer's tier under rb-021: 72 hours for premium customers, 120 hours for standard customers, and a standard offer of 10%.
- There is no blanket refund for an incident, and no refund before the threshold is reached.
- If the dispatch desk moves orders to another carrier, offer the customer an expedited re-shipment under rb-024 where stock allows.
- Orders the carrier later confirms as lost are handled under rb-013.

## Escalation

- Supervisor: any suspected outage of ten or more orders, at once.
- L1 to L2: individual orders within the incident that reach the goodwill threshold, with a recommendation.
- The supervisor informs the dispatch desk lead, who decides whether to stop booking the affected carrier.
